### secure-check-update-release (E-035 - E-041)
- **E-035** - `crates/axiom/src/update/source.rs` - the configured release source: an update may only come from an allowlisted owner/repo/channel and no default is invented from a component name. `UpdateSource::validate` bounds the owner, repository, channel and allowlist entries and refuses an unknown or malformed source with a named `rule`, and channel selection never guesses a repository from the component. Six tests cover the configured positive path, an unlisted repository, a channel the source does not offer and a malformed allowlist entry.
- **E-036** - `crates/axiom/src/update/trust.rs` - signed metadata freshness with rollback and freeze protection against a configured trust root. `UpdateMetadata::validate` requires a trusted signature, a signed `expires_at` and a monotonic `metadata_version`, refusing an expired (`metadata_expired`) or rolled-back (`metadata_rollback`) document; HTTPS is treated as transport, never as proof of publisher. Seven tests cover a valid document and the expired, rolled-back, unsigned and untrusted-root negatives.
- **E-037** - `crates/axiom/src/update/check.rs` - the cached, TTL- and offline-aware version check. `decide` serves a cache inside the effective TTL (24 h plus bounded jitter) and asks the network only when due; `--offline` and a disabled auto-check contact nothing; a transport failure reports `offline`/stale with the last successful check and never `current`; and `run_check` refuses any transport that reports an artifact download (`implicit_download`), so a check can never fetch or run an installer. Eight tests, including the TTL/jitter boundary and the implicit-download refusal.
- **E-038** - `crates/axiom/src/update/resolve.rs` - the ecosystem compatibility set. `resolve` parses SemVer itself, rejects every candidate that breaks the component, channel, spec-pin, graph-schema, control-API, queue-schema, revision or artifact-hash constraint with a named rule, keeps those rejections for the report, and selects the highest compatible release - never the newest publication time or revision. Seven tests, including prerelease-on-stable, queue/control-newer refusals and an older-than-installed candidate.
- **E-039** - `crates/axiom/src/update/plan.rs` - the update and migration plan. `build_plan` records per-component actions, downloads, migrations, the required backup, the service drain, host reconnects, bootstrap changes and rollback feasibility, then seals the frozen contract digest through the single canonical `crate::plan` encoder (no second encoder). A major or queue-schema migration, a trust-root change, a host-config rewrite or a rollback-feasibility gap each raise an approval requirement, and `require_approval` reports `plan_requires_approval`/`approval_stale`; `admit` refuses an unapproved or stale plan. Seven tests cover the sealed plan and the approval, staleness and invalid-plan refusals.
- **E-040** - `crates/axiom/src/update/drain.rs` - bounded service drain before activation. `drain` pauses new work, waits for in-flight readers/workers up to a bounded deadline (30 s default, 0-300 s accepted) and resumes; on timeout it returns `TimedOut` with `new_work_paused=true` and never kills. `DrainPolicy.allow_forced_kill` defaults to `false`, and `force_kill` refuses with `forced_kill_refused` unless it is explicitly permitted, so a forced kill is never the default update path. Eight tests, including the timeout boundary and the refused forced kill.
- **E-041** - `crates/axiom/src/update/backup.rs` - consistent, hash-verified DB and managed-state backups. `create_backup` copies each target into a caller-supplied directory and records its SHA-256 and size; `verify_backup`/`verify_backup_set` refuse a missing (`backup_missing`), short (`backup_size_mismatch`) or altered (`backup_hash_mismatch`) copy; and `require_backup_for_irreversible` refuses an irreversible migration when the backup set is absent or empty. Five tests use a real temporary filesystem.
- **E-035 - E-041** - real gate on this host: `rust-verify.ps1 -RepoPath <worktree> -Image axiom-rust-git:1.85 -Memory 6g -Offline -Gates fmt,clippy,test` -> `fmt=0 clippy=0 test=0`, `-p axiom --lib` 202 passed / 0 failed (report `_coord/logs/L14-E035-E041.rustgate.2.txt`). Limitations, not claimed as done: no live GitHub release endpoint is contacted (the transport is an injected counting double), no real running daemon is drained and no live daemon database is backed up; `update apply`, release publishing and state-aware rollback remain E-042..E-045, and no `update` CLI command is implemented here.
### v2-platform-slice (V2-002, V2-006, V2-007, V2-009, V2-013, V2-018)
- **V2-002** - `crates/bootstrap/**` - the bootstrap release boundary as a checkable workspace witness rather than a runtime. `witness()` re-reads the real manifests and reports the single workspace version, each member's `version.workspace` inheritance and whether any member looks like a standalone installer (`INSTALLER_NAME_MARKERS`), while `read_manifest`/`workspace_version`/`workspace_members` fail closed on a missing, malformed or version-divergent manifest; `BOOTSTRAP_ENGINE_CRATE`/`BOOTSTRAP_ENGINE_DIR` pin the engine to `crates/axiom/src/bootstrap`, so a second core version or a separately versioned installer process cannot appear silently. Eight tests run against the actual worktree plus the negatives (a member declaring its own version, a missing member, a malformed manifest, an installer-looking package). Root `Cargo.toml` gained only additive `members` entries for `crates/platform`, `crates/config`, `crates/migration` and `crates/bootstrap`, and `Cargo.lock` was regenerated for exactly those packages - no other workspace wiring changed.
- **V2-006** - `crates/platform/src/state_root.rs` - per-user state resolution. `resolve_state_root` accepts an `AXIOM_HOME` override only after canonicalizing it, and refuses a relative, non-directory, link/reparse or non-local (shared/cloud) root with a named reason; the platform defaults are native and local (`XDG_STATE_HOME/axiom` with a real-`HOME` fallback on Linux, `LOCALAPPDATA\axiom` on Windows, `Application Support/axiom` on macOS). `ensure_state_root` creates the directory exactly once, verifies the created result by observation instead of trusting the create call's return value, and refuses a destination that is not private to its owner; the host probe sits behind an injectable `StateRootProbe`, so a host that cannot observe ownership records `None` rather than claiming private. 17 tests cover the override, all three defaults, every refusal, the create-failure path where the host reason must survive verbatim, and a re-run that must not re-create.
- **V2-007** - `crates/config/src/bindings.rs` - logical repository bindings that survive a checkout move. A `RepoBinding` keeps the logical id, output owner key and storage class separate from the machine-local absolute root; `PortableBindings::from_private` projects the publishable view and can prove it contains no absolute path; `validate_active_writers` refuses a duplicate active output writer, a writer alias, a root alias and an overlapping output namespace (`duplicate-output-writer`, `duplicate-output-writer-alias`, `binding-root-alias`, `output-namespace-overlap`, `private-binding-required`); and `resolve_binding` answers a logical lookup without consulting a stored path. 14 tests cover the positive resolve and every refusal.
- **V2-009** - `crates/migration/src/discover.rs` - read-only discovery of both legacy spellings independently. `discover_from_paths` refuses an unsafe path before inspecting anything, and `plan_discovery` returns `MIGRATION_CONFLICT` instead of a plan when two legacy sources differ, when a present source is unhealthy, when legacy content cannot be compared with an existing V2 target, or when the inventory holds more legacy sources than the two defined spellings - it never guesses. Identical content yields an explicit dedupe decision with the leftovers named. 14 tests; the module performs no filesystem access and `NO_DESTINATION_WRITES` is a constant, not a claim. The shared typed error carries the `MIGRATION_CONFLICT` decision in its message plus allowlisted `rule`/`observed` details, and the test asserts `dropped_details() == 0`, because `graph-core`'s detail allowlist silently discards an unknown key such as `code`.
- **V2-013** - `crates/platform/src/path_key.rs` and `collisions.rs` - portable path identity. `PathKey::new` refuses an absolute, drive-qualified, traversal, reserved-name, control-character or over-budget spelling (checked per segment and for the whole path) while preserving the observed bytes verbatim, and the detector classifies case-only and Unicode-normalization equivalence without lowercasing the stored identity or rewriting a source path; a duplicate spelling is a defect rather than a silent dedupe, and an unsafe spelling in a set is reported as invalid rather than as a collision. NFD is implemented from generated tables (`unicode_tables.rs`, produced by `tools/gen_unicode_tables.py`) with canonical ordering by combining class, because the pinned registry has no `unicode` crate. 18 tests, including the byte-budget boundary.
- **V2-018** - `crates/platform/src/guard.rs` - the frozen native guard ABI: the guard directory and its two frozen lock names, the single acquisition order and the reverse release order, no upgrade and no recursive acquire, a bounded wait (5 s default, 0-60 s accepted, no unbounded blocking) with 25 ms doubling retries capped at 250 ms and a cancellable wait, plus crash release and retention GC that refuses to delete a reader-pinned generation or a partially exposed current pointer. Acquisition, release and the wait primitive are injectable, so the policy is tested without a live lake; 17 tests cover the participant plans and ABI parity, the timeout boundary, the cancelled wait, a guard path that is not a directory, and release after a crashed holder.
- **V2-002, V2-006, V2-007, V2-009, V2-013, V2-018** - real gate on this host in `axiom-rust-git:1.85` (`--memory 6g`, `CARGO_BUILD_JOBS=2`): `cargo fmt --all -- --check`, `cargo clippy --locked --workspace --all-targets --offline -- -D warnings`, `cargo build --workspace --locked --offline` and `cargo test --workspace --locked --offline --no-fail-fast` all exit 0; 883 passed / 0 failed across 43 suites, of which this slice owns 88 (`axiom-platform` 52, `axiom-config` 14, `axiom-migration` 14, `axiom-bootstrap` 8). Limitations, not claimed as done: every gate ran in the Linux container, because native MSVC is broken on this host, so no native Windows or macOS run, no Windows share-mode or ACL evidence and no live lake are exercised; the Windows share-mode pin is compiled out in the container and is therefore `not_run`; `crates/platform/src/guard.rs` keeps its own Windows pin handle because `graph-core`'s Windows lock uses `FILE_SHARE_DELETE` and diverges from the frozen ABI (`crates/graph-core/**` is outside this slice's write scope); V2-030/V2-031/V2-032 remain `not_run` on this host and are not part of this slice; the daemon-facing adapters that would wire these policies into a running process are deferred, because `crates/axiom/**` is owned by other lanes at this revision.
### cross-component failure injection (F-011 - F-015, F-018, F-021, F-022)
- **F-011** - watch save-burst injection: `tests/watch_save_burst.py` drives a real filesystem tree and proves the coalescing contract - a five-write burst on one path coalesces to one batch so analysis work drops, releasing on the hard max wait loses no path, and distinct paths release together - while two negative legs keep the shortcut honest: a naive per-burst dedup indexes stale content, and an overflow of held paths escalates to `full_scan_required` instead of silently dropping paths. Positive and negative leg counts print with `ok:`; any divergence exits 2.
- **F-012** - watcher overflow and rename inventory: `tests/watch_overflow.py` runs on a real tree and proves the inventory finds every final state including deletes and untracked additions, that HEAD equality does not skip the scan, and that a case-only rename is observed as a rename rather than a lost file; three negative legs refuse the digest-only shortcut that misses an untracked file, the "in both sets so unchanged" predicate that misses delete-then-recreate, and the replay of already-delivered hints while a scan is required.
- **F-013** - worker crash before and after acknowledgment: `tests/queue_crash.py` models the documented lease and fence state machine - recovery keeps the fence and the next claim raises it, a late result from an expired lease is rejected, a crash after the write is re-claimed instead of lost, and an edit during analysis stays dirty - with three negative legs for a non-increasing fence, an expired-lease owner and a naive same-fence predicate. The real-code command (`cargo test --locked -p graph-queue claim ack recover`) is recorded as `not_run`: the Rust crates were not built or linked on this host.
- **F-014** - concurrent edit against generation: `tests/queue_concurrent_edit.py` keeps `desired_generation` ahead of the generation an in-flight worker read, so the next batch indexes the latest content and a revert is not mistaken for an unchanged file; four negative legs refuse an unconditional dirty delete, a generation the worker never read, a non-newer generation and a content-hash-only check on a revert. Real content digests are compared; the Rust oracle command is recorded as `not_run` for the same reason as F-013.
- **F-015** - publish crash at every outbox boundary: `tests/publish_crash.py` runs a real SQLite database with a real staging directory and injects a fault at four boundaries of the publish sequence (database commit, generation creation, pointer swap, outbox acknowledgement). Each boundary converges to exactly one revision, one `PUBLISHED` row, one published generation and a pointer naming it, and a second recovery is idempotent; three negative legs prove a duplicate published row violates the primary key, a re-acknowledgement is a no-op, and a gap-free guard refuses an unbacked swap.
- **F-018** - storage failure injection: `tests/storage_failure.py` keeps the current snapshot intact under a real `PermissionError` and injected disk-full and short-write faults, and proves the queue, outbox and user-facing errors preserve the information needed to recover; two negative legs refuse a swallowing writer that advances the pointer anyway and a silent inventory drop. A real `ENOSPC` leg is not run - it needs a loopback or quota mount or an administrative tool - and the harness says so rather than claiming it.
- **F-021** - staged and merged checkpoint accuracy: `tests/git_checkpoint.py` uses the real `git` program and argv and proves the produced graph matches the exact tested source tree (staged wins over the worktree, a merged source reproduces, regeneration is deterministic); the decisive negative leg performs a real `merge=union` of the generated file, shows the result diverges from regeneration, and rejects it - the rule the git-checkpoints guide already states. Two further negative legs refuse a worktree-generated checkpoint claimed as staged and stored bytes that drift from a mutated source.
- **F-022** - SQLite upgrade and restore: `tests/sqlite_migration.py` runs the real shipped DDL against the real engine and proves a failing migration rolls back, and that a `VACUUM INTO` backup taken with WAL frames outstanding restores to the committed state; three negative legs refuse a raw `.db` copy that loses committed WAL rows, a newer database and a checksum mismatch. The runtime baseline is not certified: the host engine is SQLite 3.50.4 while the documented baseline needs >= 3.51.3, so the harness prints the actual version and marks that leg `not_run` instead of passing it.
### managed-multi-repo-bootstrap (E-013 - E-021)
- **E-013** - Approved repository set: `crates/axiom/src/bootstrap/repos.rs` (with the new `crates/axiom/src/bootstrap/` module tree and its `lib.rs` wiring) turns explicit solution bindings into an admission check instead of a lookup. A declared root must exist, be a directory, be readable, have exactly the declared repository directory name and - when the solution pins one - the declared canonical origin, or it is rejected with a stable rule (`repository-absent`, `repository-not-a-directory`, `repository-inaccessible`, `repository-name-mismatch`, `repository-remote-mismatch`, `repository-root-unsafe`, `repository-root-duplicate`, `repository-id-duplicate`). A similarly named checkout such as `axiom-graphd-old` can never stand in for `axiom-graphd`, a same-named fork is refused by origin, and unsafe (`..`, relative) or duplicated bindings are refused before any host read, so no repository is silently substituted. Observed state enters through `RepoProbe`; `LocalRepoProbe` reads metadata and `.git/config` (a `.git` directory or a worktree `.git` file with `gitdir`/`commondir`) and never writes. A partial set is a result rather than an error - unaffected repositories proceed and refusals are reported - while a solution with nothing approved is refused with `solution-has-no-approved-repository`.
- **E-014** - Managed marker parsing: `crates/axiom/src/bootstrap/markers.rs` finds the single owned span between `<!-- axiom-graph:begin -->` and `<!-- axiom-graph:end -->` and refuses anything ambiguous, so the writer never guesses. Marker text inside a Markdown code fence (``` or ~~~, up to three leading spaces, a closing run at least as long with a blank remainder) is a quoted example and is ignored; a marker line is recognised after trimming surrounding whitespace, and a leading UTF-8 BOM neither hides the first marker nor becomes part of the span. A lone marker is refused `markers-unbalanced`, more than one pair or a doubled begin/end is refused `markers-duplicate`, and an inverted span is refused `markers-out-of-order`; every refusal is a `MarkerConflict` value rather than a byte range, and the parser is read-only, so refusing never alters human text. The whole `fixtures/bootstrap` corpus is replayed by the tests: the four marker-conflict vectors are refused and `markers_in_fence` yields no marker outside its fence.
- **E-015** - Encoding- and newline-preserving text handling: `crates/axiom/src/bootstrap/text.rs` makes "change only the owned span" a type instead of a habit. `SourceText::decode` accepts a UTF-8 document with an optional single leading BOM and refuses any other encoding with a conflict carrying the stable rule `text-encoding`, leaving the caller's bytes untouched; `SourceText::encode` returns those bytes verbatim, so the corpus before-states round-trip byte for byte. The dominant newline (`\r\n` when the document contains one, `\n` otherwise) is also the newline of the written block, and `render_block` trims the template's surrounding newlines and re-expresses it in that convention, so a CRLF repository is never converted to LF and an LF repository never gains a CRLF. `replace_span` splices the block between the bytes before and after the span (a leading BOM therefore stays outside it and is never re-encoded), `append_block` keeps the whole original document as an exact prefix and inserts one newline when the file already ends with one or a blank separator line otherwise, and `replaces_only_span` states the preservation property once for the planner, applier and verifier. A span that does not fit or is inverted is refused with `text-span-out-of-range` rather than clamped. The whole `fixtures/bootstrap` corpus is replayed: 12 before-states round-trip, zero are refused, the four append vectors keep their original bytes as a prefix and the two replace vectors change nothing outside their span.
- **E-016** - The separate managed policy file: `crates/axiom/src/bootstrap/policy.rs` fixes both properties a pointer block needs. First, the managed block must actually point somewhere - `block_points_at_policy` requires the literal `.axiom/agent/POLICY.md` and the word `read`, so a block that only mentions the path in prose, says `readme`, or names no policy at all is refused with `policy-pointer-missing` instead of written; the shipped block template and the policy template are asserted directly, and the policy's own `Managed policy version:` line is parsed so the version recorded in the ownership manifest can be read back out of the file. Second, a policy file is only ever managed when an ownership manifest records its digest: `PolicyVerdict` decides `Create`, `Unchanged`, `Edited`, `Unowned` or `Removed` from the observed and recorded digests, and the unowned case is decided *before* the digest is compared, so a pre-existing `.axiom/agent/POLICY.md` is never adopted and never overwritten even when its bytes are byte-identical to the shipped template - it is refused `policy-unowned`. A human edit to an owned policy is `policy-edited` and a removed owned policy is `policy-missing`; both refuse and preserve, and `.axiom/agent/POLICY.local.md` stays the human override path bootstrap does not own. The corpus is replayed: exactly the three vectors whose reason is `unowned` or `policy` are refused, nine before-states create the policy and four already match.
- **E-017** - Ownership hashes and template version: `crates/axiom/src/bootstrap/ownership.rs` writes `.axiom/agent/bootstrap.lock.json` as the record of exactly two artifacts - the managed span of `AGENTS.md` and the managed policy file - plus the template version that produced them, and nothing else. The single constructor `Ownership::new` computes both digests from the bytes it is handed, so the manifest cannot claim ownership of content bootstrap did not write, and the record is a fixed four-key document with no per-path map, listing or timestamp to drift out of date. `parse` refuses a manifest this build cannot trust rather than half-understanding it: unreadable or truncated JSON and non-UTF-8 bytes are `ownership-malformed`, an unknown schema version or empty template version is `ownership-schema`, and a digest that is not a canonical lowercase SHA-256 is `ownership-digest`. `detect_drift` then recomputes both digests from the repository before any update, so a human edit inside the owned block is `ownership-block-edited` and a removed block is `ownership-block-removed` (checked first, as the contract's decision order requires), while an edited or removed policy is `ownership-policy-edited` / `ownership-policy-removed`; each refusal carries the word the contract uses for that failure and preserves the human bytes. The corpus is replayed: all six before-states that carry a manifest re-encode byte-identically - which is what makes a re-apply a no-op - and exactly the three drifted vectors are refused, while the three still-current ones stay current.
- **E-018** - Reviewable multi-repository plans: `crates/axiom/src/bootstrap/plan.rs` turns the per-slice verdicts into one document an operator can read before anything is written, and the read-only property is structural rather than promised - `RepositoryReader` has a single method that can only read, `LocalRepositoryReader` is the only filesystem adapter and its only filesystem call is `fs::read`, so planning a repository that has no `.axiom` directory cannot create one (asserted against a real temporary directory, whose recursive listing is unchanged afterwards). Each repository in the plan carries its change classification (`append`, `replace`, `unchanged` or `conflict`) exactly as `fixtures/guides/bootstrap.md` names them, the managed-block hash before and after, and, for every file it would write, the destination-relative path, the before- and after-SHA-256, the exact bytes and a proposed unified diff; `render` prints the whole thing for review and `conflicts` lists the refusals. Refusals do not abort the run: a marker shape, markers without ownership, a non-UTF-8 file, an unowned policy and a human edit inside the owned block each become a `conflict` entry carrying the stable rule from `markers`, `text`, `policy` or `ownership`, while unaffected repositories are still planned, so the aggregate can report per-repository outcomes and exit 20 for a partial run. A plan is bound to its inputs: the digest is a SHA-256 over the canonical bytes of the document with the digest field empty, `to_canonical_bytes` is what an operator approves and `parse` refuses a body that no longer hashes to its recorded digest (`plan-digest-mismatch`), so a plan edited after approval cannot be applied. The whole corpus is replayed through the real adapter: five append, two replace, one unchanged and eight conflicts, each matching its documented outcome and reason.
- **E-019** - Before-hash verification and the per-repository apply lock: `crates/axiom/src/bootstrap/preconditions.rs` makes "re-check the before-hashes, then take the lock" a checked precondition instead of a promise. `verify_repository` re-reads every file the plan would write, compares its current SHA-256 with the `before_sha256` the plan recorded, recomputes the managed block from the current `AGENTS.md` and compares that with the plan's `before_block_sha256`, and refuses any mismatch with the stable rule `plan-stale` naming the field, the expected and the observed hash - so a plan whose inputs changed after approval is rejected before its repository is written, and an `unchanged` repository whose block was edited is caught even though the plan proposes no file. The bound root must still be a directory (`precondition-root`) and a repository the plan already refuses is rejected (`plan-repository-conflict`). `ApplyLock::acquire` creates one lock file per repository under `AXIOM_HOME/bootstrap-locks/<id>.lock` with a create-only exclusive open, so a cooperating apply that races the same repository loses with `apply-lock-held` (`WorktreeBusy`) and is told who holds it rather than overwriting the holder's token; an identifier that could escape the lock directory is refused `apply-lock-id-unsafe`, and the lock is removed only while it still records this holder's token, so dropping a failed apply releases it and no process deletes another's lock. `begin_apply` composes the two in the guide's order - lock first, then re-verify, releasing the lock when the verification refuses - and `PreconditionHost` keeps the policy host-free: `LocalPreconditionHost` is the only filesystem adapter and an in-memory double exercises every refusal. Tests cover the positive verify-and-release, a stale target, two applies that cannot interleave and then proceed once released, a foreign lock that is preserved, unsafe identifiers, an unbound root, a conflict plan and a real lock taken and removed by the production host.
- **E-020** - Journaled, backup-protected application: `crates/axiom/src/bootstrap/apply.rs` is the only half of bootstrap that writes, and it is built to fail safely. Per repository it takes the apply lock and re-verifies the before-hashes (E-019), backs the affected bytes up under `AXIOM_HOME/bootstrap-backups/<id>/`, writes a `bootstrap-journal/<id>.json` *intent* before touching an owned file, writes the owned files with `.axiom/agent/bootstrap.lock.json` last, verifies the written hash against the approved after-hash and recomputes the bytes outside the managed block, and only then marks the journal complete. A write that fails rolls back: every file this run already wrote is restored from its backup, and a file whose current hash no longer equals the after-hash this run wrote is left untouched and reported (`RollbackRefused`) rather than discarding a newer human edit; a missing backup is refused `apply-backup-missing`. The aggregate applies one repository at a time and reports every repository independently - `Applied`, `Unchanged`, `Refused` (a plan conflict or a stale/locked precondition), `RolledBack` and `RollbackRefused` - with `exit_code()` returning `PartialOperation` (20) when some repositories were updated and others were not, so bootstrap never claims all repositories were updated when only some were. `BootstrapHost` keeps the write path host-free: `LocalBootstrapHost` writes through a temp file and rename, and `MemoryBootstrapHost` can make a chosen write fail so rollback and the refused-rollback boundary are exercised. Tests cover the applied-and-journaled path, a failed write that restores the earlier file and leaves the failing one absent, a rollback that refuses to discard a newer edit, a two-repository run that reports one stale refusal and one success at exit 20, a conflict plan refused without a write, the outside-content comparison and a real apply through the production host.
- **E-021** - Idempotence and drift reporting: `crates/axiom/src/bootstrap/verify.rs` is the read-only close of the bootstrap loop and the gate that tells a managed edit apart from a human one. It re-plans the repository from its current bytes (E-018) and classifies it: `current` when the plan is `unchanged`, which is exactly the statement that a second apply writes nothing; `managed-refresh` when the owned content is intact but a template update would rewrite the block or policy in place; `unbootstrapped` when no ownership manifest exists yet; `managed-drift` when the bytes *inside* the managed block or the policy file no longer match the manifest (`ownership-block-edited`, `ownership-block-removed`, `ownership-policy-edited`, `ownership-policy-removed`); and `undecidable` for a marker shape or ownership record bootstrap will not judge. A change *outside* the managed block is reported in `human_edits` and never fails the run - bootstrap did not own those bytes and `owns_only_the_managed_span` proves the proposed write could not touch them, allowing only a span replacement or an append that keeps the whole human document as an exact prefix and refusing anything else with `verify-outside-content-changed`. `VerifyReport::exit_code` is 0 for a clean run even when a second apply would write, the drift's own status when every repository drifted, and `PartialOperation` (20) when only some did, so a partial result is never reported as a whole one. `VerifyTarget` carries the approved pre-apply snapshot so the human-edit baseline is the plan's own input; tests cover the no-op second apply, the outside-edit-versus-inside-edit distinction, a policy-only drift, an undecidable marker shape, an unbootstrapped repository, the partial exit 20 and the write-scope boundary.
### documentation-guides (D-012 - D-014)
- **D-012** - Git checkpoint and merge guide: `docs/guides/git-checkpoints.md` separates the three states an operator conflates - live ignored data under the project output root, the optional staged export that only an explicit checkpoint command writes, and merged-source regeneration after the source merge is final - and states the rule that makes the rest safe: a generated graph is never merged, it is regenerated from merged source. It fixes the source selection (index bytes by default, a stability certificate for the worktree, a pinned commit for CI), the four-step merge order (resolve source, regenerate, validate catalog references, run tests), the refusals that must stay refusals (union merge, hand-picking a graph side, a worktree fallback for a path missing from the index, `WORKTREE_BUSY` at exit 6, `NOT_READY` at exit 4 for a stale checkpoint) and the size budgets. The page states plainly that the checkpoint argv surface is not implemented at this revision, that tasks E-023, E-024, E-025 and F-021 are still `todo`, and that this guide has no Rust oracle: `fixtures/guides/driver.py` is the only executed check, and the `absent_paths` list in `fixtures/guides/manifest.json` fails the driver if the absent oracle ever appears without the guides being updated with it.
- **D-013** - Multi-repo bootstrap operations guide: `docs/guides/bootstrap.md` defines the two owned artifacts (the small pointer block in `AGENTS.md` and the canonical `.axiom/agent/POLICY.md`) and the managed-merge algorithm's exactly-one outcome per repository - **append** when the file is absent or has no markers, **replace** only the block whose hash matches the last applied hash, **adopt only** through an explicit plan, **conflict** on duplicate, missing, nested or out-of-order markers, on a human edit inside the owned block, on a whole-file policy edit or on a manifest that names a missing policy, and **unchanged** when a re-apply would change nothing. Plan is read-only and is not approval; apply re-verifies root bindings, ownership and before-hashes and refuses a stale or digest-less plan.
