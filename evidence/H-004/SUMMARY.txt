## Deliverable

crates/config/src/solution.rs is the new reader. It derives exactly two tables
from ONE accepted schema_version 2 solution document plus its owner-only bindings:

  * one MembershipClaim per projects[] entry (M2/M4/M5/M6 + B-013 overlap/duplicate),
  * one ServiceAlias per semantic_links[] entry that carries a route_prefix,
    keyed by normalize_service_key(route_prefix) and always resolving to the
    link's TARGET project (contract section 3).

RegisteredSolution::resolve implements contract section 4 exactly: protocol
scoping, the same normalizer, equality or a '/' boundary prefix, then one of
Resolved / Unresolved (alias-unresolved-host) / Ambiguous (alias-ambiguous-host).
A repeated declaration of one project is not an ambiguity; no tie is broken by
list position. read_registered_solution validates the WHOLE claim set and returns
no RegisteredSolution on the first failure, so a refused registration writes
nothing (M1); no row and no file is written anywhere in the reader.

The registered document is the ONLY source of the L3 cross-service alias map:
SolutionMapping's alias table is private with no mutator, its only constructor is
SolutionMapping::from_registered_aliases(<RegisteredSolution>::l3_aliases()), and
both consumers of the join in this repository now read a registered document:

  * crates/graph-analyze/src/l3/http_join.rs unit tests read REGISTERED_SOLUTION /
    AMBIGUOUS_SOLUTION through read_registered_solution;
  * the F-006 vector harness crates/graph-analyze/tests/l3_fixtures.rs projects
    each vector's `link <source> <target> <protocol> <route-prefix>` directives
    into a solution document and reads it back with the same reader. The old
    hand-written `alias <host> <project>` grammar directive is gone, and the five
    vectors now carry portable project ids as M2 requires.
